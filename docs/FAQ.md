## Q1：这是 Google 或 Mozilla 官方应用吗？

不是。PG Proxy 是独立社区项目，使用 Google AI Studio Playground 网页会话提供兼容接口。Google、Gemini、Labs、Mozilla、Firefox 等名称和标识归各自权利人所有，使用相关组件或视觉元素不表示官方认可或合作。

它也不是 Google 官方 Gemini API SDK。网页协议可能变化，账号资格、地区、额度和模型权限仍以 Google 的实际要求为准。

## Q3：怎样核对安装包？自行构建是否更安全？

先核对下载来源、版本、APK SHA-256 和签名证书。发布文件的校验值用于确认文件一致，签名用于确认签名身份；两者都不能代替代码审查。具体命令见[安装与签名](MAINTENANCE.md#3-安装与签名)。

自行构建能让你控制源码和工具链，但仍依赖本机环境及第三方依赖的可信度。源码公开、自行编译或扫描未报警都不等于绝对安全。使用前应了解应用处理的登录会话与网络请求范围。

## Q4：手机运行时需要电脑、Termux 或 Root 吗？

不需要。安装后，登录、凭证保存、API 服务和配置管理都在应用内完成。Gecko 登录浏览器、Python 服务和 Go WAA 运行时随应用运行，无需另行部署 AIStudio2API 或其他反代服务。

从源码构建需要开发电脑和工具链。当前完整构建流程以 Windows 为基准，手机运行条件与构建条件是两回事，见[维护文档](MAINTENANCE.md)。

## Q5：支持哪些 Android 设备？为什么安装失败？

最低支持 **Android 9 / API 28**，源码可构建 `arm64-v8a` 与 `x86_64`。普通 ARM64 手机选择 ARM64 包；x86_64 主要用于对应模拟器，当前不支持 32 位 ARM / x86。

已有 vivo V2505A、Android 17、4 KB 内存页的 ARM64 真机接口记录，以及 Pixel 10 x86_64 模拟器记录。前者不能代表所有厂商或 16 KB 页设备，后者不能替代真机，范围分别见[真机验收](PHYSICAL_DEVICE_TEST.md)与[模型能力验收](MODEL_CAPABILITIES_TEST.md)。

安装失败时检查系统版本、架构、剩余空间和签名。同一包名使用不同签名，通常不能直接覆盖安装。不要直接卸载或清除数据排错，这会删除私有配置、凭证和登录会话；先按[维护文档](MAINTENANCE.md)核对安装错误。

**0.3.0 沿用 0.2.0 的正式签名，正常覆盖更新可保留配置、凭证和浏览器会话。** 仅旧 0.1.0 正式签名包涉及历史签名断代：0.2.0 已更换签名，从旧 0.1.0 升级到当前版仍需先记录必要设置，再卸载旧版、安装新版并重新登录。卸载或清除数据会删除私有资料；仅清数据不能解决签名不同的覆盖安装冲突。自行构建包请单独核对其签名。

## Q6：Google AI Studio 支持哪些地区？

以 [Google 官方适用区域](https://ai.google.dev/gemini-api/docs/available-regions?hl=zh-cn)为准，支持范围和账号条件可能更新。

**2026-10-29** 核对时，该页面标注更新于 **2026-10-22**，中国大陆、香港、澳门、朝鲜、伊朗、叙利亚、俄罗斯、白俄罗斯未出现在支持清单中。这是部分未支持地区的记录，不是完整“封禁名单”，也不能据此推断其他地区一定可用。年龄、账号类型等资格仍需查看官方说明。

PG Proxy 不改变这些准入条件，也不保证任何地区长期可用。

## Q7：无法添加凭证、进入登录页失败或登录后白屏，应该先检查什么？

先查看 **概览 → 网络信息** 的出口地区、来源和查询时间，必要时刷新，确认网络环境是否符合 Google 的适用条件。再检查网络连接、DNS、系统时间和 Google 页面本身能否打开。

加载失败后可按页面提示重试或打开 Playground；返回凭证页后，也可继续尚未完成的登录。密码、验证码、网站条款和账号安全确认由用户亲自完成。

vivo 真机测试曾发现两步验证后的 `accounts.youtube.com` 跳转被拦截并出现错误 `17`。修复后仅放行该精确主机的 HTTPS 默认端口／443，原会话已恢复导入并通过真实检查。该修复不能解释所有错误 `17`，详见[登录修复记录](PHYSICAL_DEVICE_TEST.md#登录问题与修复验证)。

网络卡片只反映查询服务看到的出口。VPN、应用分流和浏览器／后端路由差异可能让 Google 使用其他出口；显示支持地区不能单独证明登录、WAA 或生成可用，需结合实际错误判断，见[网络信息说明](NETWORK_INFO.md)。

## Q8：为什么 Google 提示“此浏览器或应用可能不安全”？

Google 可能基于账号状态、登录环境或服务策略拒绝登录。当前应用使用 Gecko 与原生 Firefox UA，没有切换 Chrome UA 的选项，也不保证所有账号都能登录。

按 Google 页面要求完成账号验证，避免连续高频重试。持续失败时，可提交 Android 版本、应用版本、复现步骤和脱敏后的错误；不要提交密码、验证码或 Cookie，也不要通过关闭证书校验排错。

## Q9：凭证导入成功，为什么还要“检查凭证”？

**导入成功表示会话已保存；检查成功表示该次真实生成可用。** 检查会向 Playground 模型发送短文本请求，覆盖会话、认证、WAA 和生成链路，需要网络，也可能消耗上游额度。

一次成功不保证全部模型可用或会话永久有效。Cookie 到期、退出 Google、账号安全事件和上游策略变化都可能要求重新登录。

## Q10：登录会话、Cookie 和密码保存在哪里？

密码和验证码由用户在 Google 页面输入，应用不读取密码字段。服务凭证保存在应用私有目录，由 Android Keystore 支持的 AES-GCM 加密；Gecko 会话也位于应用私有存储。

不要分享 Cookie、浏览器目录、设备备份或带认证信息的抓包。卸载、清除数据或系统密钥丢失可能使凭证无法恢复；设备或应用被攻破时，加密存储也不能保证会话安全。

## Q11：禁用凭证与删除凭证有什么区别？

| 操作 | 行为 |
| --- | --- |
| 禁用 | 停止分配新请求，保留凭证和会话，便于稍后启用 |
| 删除 | 阻止新分配，等待在途请求结束后清除服务凭证，并尝试清理对应浏览器会话 |

清理被占用或发生异常时可能需要重试，设置中提供登录资料清理入口。两种操作都不等于撤销 Google 服务端的全部会话；怀疑泄露时，还应使用 Google 账号的安全管理功能。

## Q12：如何添加多个账号？轮询会自动解决额度限制吗？

每次通过 **凭证 → 添加** 登录一个账号，各凭证使用独立浏览器会话。不要在同一会话叠加多个 Google 账号后切换 `authuser`；当前实现拒绝非默认账号路由，避免保存错账号。

请求采用**全局串行、按请求轮询**。另一个账号即使空闲，也不会并行发起生成；一次生成及其续写始终使用同一凭证，结束或取消并完成清理后，队列才继续。

假设 A、B 均可用且支持模型，A 正在生成，第二个请求的排队超时为 30 秒：

| 场景 | 第二个请求的行为 |
| --- | --- |
| 等待 8 秒后 A 结束 | 随即按轮询顺序选择 B，不必等满 30 秒 |
| 等待满 30 秒仍未轮到 | 返回 `429 / account_busy` 和 `Retry-After: 5`，不选择账号，也不继续后台执行 |
| 轮到时 B 已停用、冷却或不支持模型 | 重新检查可用凭证；可能使用 A，或返回无可用凭证／模型错误 |

**排队超时是最长等待时间，不是账号切换间隔。** 超时不会推进轮询位置。目录、计数、凭证检查等操作也共享队列；其中计数不推进生成轮询。设置中的请求超时限制上游每次读写等网络阶段，连接超时固定为 30 秒；它不包含排队，也不是整段流式响应的总时长上限。

待登录、校验异常、删除中、冷却中或停用的凭证不会正常分配。生成提交后遇到上游错误，不会自动换账号重放，避免重复生成或消耗额度。

轮询不会合并账号权限或扩大额度。A/B 调度已由模拟测试覆盖，两个真实 Google 账号的端到端轮询仍需独立验证。遇到 429 应按提示等待，不要把多账号理解为消除所有额度限制。

## Q13：模型列表为什么与别人不同？支持 Build 或所有 Gemini 参数吗？

模型通过登录会话在线读取 `ListModels`，内存缓存最多 5 分钟，再按当前已实现的能力筛选。账号、地区、时间和 Google 调整都可能影响列表。升级后应刷新客户端模型；必要时重启 PG Proxy 服务清除旧缓存。

0.1.0 测试时网页 37 项中保留了 19 个 ID，**这 19 个模型均已有真实计数和生成记录**，该阶段 517 项 Python 回归通过。结果来自 2026-10-30 Pixel 10 模拟器的分阶段修复与复测，不代表每个模型的所有组合都已验证，也不替代 0.3.0 安装包的设备运行验收，见[模型能力验收](MODEL_CAPABILITIES_TEST.md)。

0.3.0 的 Pixel 10 新包另行读取到 19 项实时目录，以 `gemini-3.8-flash` 验证生成、流式和强制 WAA 更新；这轮没有逐个模型重新生成，也没有操作真机。新包结果与复测边界见[当前验证记录](VALIDATION.md#pixel-10-新包与真实请求)。

目录不是名称白名单，也不是网页所有卡片的镜像。五个 TTS 模型缺少当前通道要求的聊天生成能力；视频生成、Live、音乐和仅用 Interactions 的模型仍未接入。未知模型的模态资料保持未知，不妨碍符合筛选条件的新模型动态进入列表。`Paid` 标签本身不会触发过滤，模型权限仍由 Google 决定。

Argon 曾因续写能力码被误过滤，现已动态支持。同一请求会在同一凭证下逐轮生成新的 WAA proof 并合并输出；默认输出上限仍取目录值，可显式设置的最大值见 `pg_proxy.proxy.limits.max_output_tokens`。**真实跨轮长输出尚未验证**，四项真机短请求不能替代该测试，见 [Argon 记录](MODEL_CATALOG_TEST.md)、[Google 模型说明](https://ai.google.dev/gemini-api/docs/models/gemini-4-argon)与[迁移指南](https://ai.google.dev/gemini-api/docs/latest-model)。

项目只接入 Playground，没有 Build、旧 Google CLI / Cloud Code Assist 或额度回退。参数和媒体还受具体接口限制，完整说明见[模型与接口文档](MODEL_API.md)。

## Q14：客户端怎样连接？默认端口和密钥是什么？

新安装默认端口 **`8888`**、接口密钥 **`123`**。启动服务后，同一手机的 OpenAI 客户端使用 `http://127.0.0.1:8888/v1`；原生 Gemini 请求使用 `/v1beta` 前缀。端口或密钥修改后，客户端也需同步。

支持 Bearer、Basic、查询参数 `key` 和 `x-goog-api-key`。请更换默认密钥，尤其在启用局域网前；优先通过请求头传递，避免密钥进入 URL 历史。这里填写的是 PG Proxy 接口密钥，不是 Google API Key 或 Cookie。

OpenAI 客户端请选择 **Chat Completions**。兼容层会忽略未实现的可选参数，处理 `null`，并补全可推断的角色等默认值；缺少模型时从在线文本目录选择。`strict`、强制工具等被忽略的约束不会因此生效，不能据此承诺所有客户端功能。四个参考客户端、具体规则与测试边界见[客户端兼容](CLIENT_COMPATIBILITY.md)。

## Q15：其他设备如何连接？能直接暴露到公网吗？

在设置中开启局域网，使用概览显示的手机局域网地址。其他设备的 `127.0.0.1` 指向它自己，不能用于访问手机。确认设备网络互通，排查访客 Wi-Fi、AP 隔离、防火墙和手机网络策略。

接口使用 **HTTP，没有内置 TLS 或公网穿透**，适合本机或可信局域网。不要直接开放公网端口；默认密钥也不能提供可靠隔离。

## Q16：常见请求错误和容量限制是什么原因？

| 状态或现象 | 优先检查 |
| --- | --- |
| 400 / 请求无效 | JSON、消息正文、媒体数据、工具历史或路径参数；未知可选生成设置已由兼容层过滤 |
| 本地接口 401 | PG Proxy 密钥及认证格式是否正确 |
| 上游会话认证错误 | Google 会话是否过期、退出或需要重新登录 |
| 403 / 权限拒绝 | 账号资格、地区、模型权限、Google 策略或 WAA；单凭状态码无法确定原因 |
| 404 | 路径与模型 ID 是否正确，模型是否仍在目录中 |
| 408 / 上传超时 | 完整正文上传超过 60 秒；检查连接，缩小附件 |
| 413 / 请求体过大 | 完整 JSON 超过 64 MiB，包含 base64 编码后的媒体；缩小输入，不会自动截断内容 |
| 429 | 上游限流／配额或本地排队超时；查看错误类型和 `Retry-After` |
| 503 / 无可用凭证 | 是否有已启用且不处于错误、冷却或删除状态的凭证 |
| 503 / 纯文本 Service Unavailable | HTTP 连接／任务达到 Uvicorn 并发上限 16；减少并发连接与请求，稍后重试 |
| 连接拒绝 / 超时 | 服务、地址、端口、网络及后台状态 |

HTTP 并发上限与排队超时分别生效，生成仍为全局串行。Schema 展开还受节点与累计体积预算限制；超限时会整体忽略当前可选 Schema 并保留正文，不提交部分约束，也不自动重发生成。需要严格输出结构时应精简 Schema 并在客户端校验结果，详见[请求入口与资源限制](CLIENT_COMPATIBILITY.md#请求入口与资源限制)。

转写的词表或 Smart 与时间戳／说话人标注冲突时，保留后者并忽略冲突设置；语言仅保留目录中的精确代码，例如 `en`，不会把 `en-US` 猜成另一种语言。缺少有效语言提示时使用上游默认行为，见[转写配置与时间戳](MODEL_API.md#转写配置与时间戳)。

先查看脱敏日志和具体错误，再决定是否修正请求、等待或重新登录，避免无限自动重试。

## Q17：后台服务会被系统杀掉吗？怎样设置更稳妥？

仍有可能。前台服务、通知和 CPU 唤醒锁只能降低中断概率，不能保证永不回收，也不能绕过用户强制停止。

在 **设置 → 后台运行** 检查通知权限、电池优化与厂商耗电管理，按系统选项允许后台活动或“不受限制”。需要锁屏持续提供接口时，可开启 **保持 CPU 唤醒**；它默认关闭，会增加耗电，停止服务后释放。

vivo 实测路径为 **PG Proxy 设置 → 后台耗电管理（应用详情）→ 电量 → 后台耗电管理 → 允许后台耗电**。默认“智能控制”曾导致通知仍在、进程却被冻结，唤醒锁也被禁用；调整后在 USB 供电条件下通过 6 分钟锁屏及真实生成。详见[真机记录](PHYSICAL_DEVICE_TEST.md)与[后台运行说明](BACKGROUND_RUN.md)。

上述 vivo 结果属于 0.1.0 阶段。0.3.0 在 Pixel 10 模拟器仅完成约 10 秒、5 次健康检查的短时后台验证，不能据此保证长期锁屏或厂商后台策略下持续运行。

应用没有开机自启、定时复活或无障碍保活。长期锁屏、Doze、网络休眠和不同厂商策略需在对应设备上验证。

## Q18：概览的 IP、网络类型和风险分代表什么？会泄露 Google Cookie 吗？

网络信息来自 IPQuery、ident.me 和 Cloudflare 的 HTTPS 查询。请求会让查询服务看到公网 IP 和常规请求信息，但不携带 Google Cookie、账号资料或接口密钥。

类型和风险分是查询服务的判断，不是 Google 的评估或安全证明。缺失字段保持未知；低风险不等于一定能登录或生成。来源、缓存和回退规则见[网络信息说明](NETWORK_INFO.md)。

## Q19：请求统计、有效凭证数量和日志为什么会变化或清零？

请求成功／失败统计公开的模型列表、模型详情、`countTokens` 及生成接口。内部状态刷新、健康检查、网络查询和凭证检查不计入；流式错误或服务端观察到的中断会影响失败计数。

统计保存在内存，后端重建后清零，不是永久账单。“有效凭证”反映最近一次检查或生成成功的记录，包含已停用但保留状态的凭证；它不是当前轮询数量或持续有效保证。日志也仅保留本次进程有限数量的管理事件，不是完整抓包。

## Q22：更新版本后要重新登录吗？如何避免丢失凭证？

包名、签名一致且符合 Android 版本码要求的覆盖更新，通常能保留私有数据；Google 会话本身仍可能过期。0.3.0 的版本码为 30，沿用 0.2.0 正式签名，可从该正式包正常覆盖更新。自行构建的签名可能与发布包不同，不能假设它们可以直接覆盖。

常规升级不要卸载或清除数据。切换签名、重装系统或清除私有存储后，应预期重新登录；项目没有承诺跨设备迁移凭证。签名与版本管理见[维护文档](MAINTENANCE.md)，不要把私有会话上传到仓库作为备份。

## Q23：升级后状态栏或常驻通知为什么仍显示旧的 P 图标？

当前桌面和通知图案均为**烧瓶＋镂空星**。vivo V2505A / Android 17 曾在覆盖安装后继续使用主题化图标缓存，屏幕上的旧 P 不一定意味着安装包仍包含旧图案。

先核对安装包，再停止并重新启动服务。仍未刷新时，可在方便时尝试重启手机；这一步不是本轮已验证方案。本轮实际验证的是通过 ADB 触发系统缓存回收后恢复新版图标，没有卸载应用、清除数据或重新登录。

标准通知小图标由 [`setSmallIcon`](https://developer.android.com/reference/android/app/Notification.Builder#setSmallIcon(int)) 指定，厂商可能重新呈现。其他设备若持续异常，请提供版本与脱敏截图；维护者诊断步骤见[通知图标与厂商缓存](MAINTENANCE.md#通知图标与厂商缓存诊断)。

## Q24：目录有完整能力信息，为什么 RikkaHub 仍缺少标签或工具设置？

服务端提供标准字段及 `pg_proxy`、`architecture`、`supported_parameters` 扩展，但客户端需要主动读取。本次参考的 RikkaHub OpenAI 提供商只读模型 `id`，Google 提供商读取 `name`、`displayName` 和 `supportedGenerationMethods`；模态、思考和工具标签仍依赖其本地 `ModelRegistry`。

请在客户端核对模型标签、上下文与功能设置。原生 Gemini 可表达的 PDF／视频也不等于 OpenAI 入口支持。RikkaHub Google 提供商当前只取 `pageSize=100` 的第一页，现有 19 项不受影响，未来更大目录需要客户端翻页，见[模型与接口说明](MODEL_API.md)。

多轮工具调用还需要原样保留 Google `thoughtSignature`。PG Proxy 原生接口保留该字段，OpenAI 入口通过 `extra_content.google` 传递；参考版本的 RikkaHub OpenAI 路径会丢失这些扩展，Google 路径有对应保留逻辑。涉及签名时优先使用原生 Google 提供商，将请求指向 PG Proxy `/v1beta`。这些结论来自固定版本的源码合同检查，不是 RikkaHub 安装包全功能实测。

## Q25：怎样统计 token？为什么缓存和批处理方法不能直接用？

调用 `POST /v1beta/models/{model}:countTokens`，提交 `contents` 或 `generateContentRequest`，两者二选一。需要系统指令或函数声明时使用后者。请求使用实际 Playground 计数 RPC，不做本地估算，示例见[模型与接口说明](MODEL_API.md)。

计数共享操作队列并纳入公开请求统计，但不推进生成轮询，也不把凭证标记为生成已验证；计数成功不能代替生成测试。

上游列出 `createCachedContent`／`batchGenerateContent` 只是能力声明。Cookie Playground 对应的认证、任务提交、状态管理及清理链路尚未实现并验证，因此不列入代理的 `supportedGenerationMethods`，也不通过公开 API Key 或 Build 回退冒充支持。已验证范围见[模型能力验收](MODEL_CAPABILITIES_TEST.md)。
