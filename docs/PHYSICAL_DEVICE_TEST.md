## 登录问题与修复验证

首次真实登录在 Google 两步验证后的跳转过程中出现“页面暂时无法打开”，错误分类 `1`、错误代码 `17`。安全诊断先记录 `accounts.youtube.com` 被域名白名单拒绝，**19 ms 后**记录页面加载错误。GeckoView 的错误 `17` 是通用未知错误，不能将所有同类错误都当作可忽略事件。

修复只增加必要的精确主机 `accounts.youtube.com`：要求 HTTPS、默认端口或 `443`，禁止 URL 用户信息；其他 YouTube 域名、相似恶意域名、HTTP 和外部协议仍被拒绝。原生 Firefox UA、证书校验，以及仅在 AI Studio 页面提取凭证的限制保持不变。导入开始或完成、页面关闭期间的迟到回调也不再覆盖导入结果。

覆盖安装修复包后，继续原有登录会话，应用自动返回凭证列表并保存 **1 份凭证**，未再出现原错误弹框。点击“检查凭证”后显示“已验证”与 **18 个可用模型**。这是本机已有会话恢复的真实验证，不代表重新创建第二个 Google 账号或所有登录分支均已覆盖。

## 锁屏后台：默认策略失败，调整后短时通过

第一轮于 **22:19（北京时间）**开始，计划锁屏 6 分钟，每 30 秒从电脑直连手机局域网 `/health`。应用已开启 CPU 唤醒，USB 调试仍保持连接，vivo 后台耗电策略为默认的“智能控制后台耗电”。

| 时间与观察 | 实际结果 |
| --- | --- |
| 锁屏后约 0.30 秒 | `/health` 返回 `200`，系统显示屏幕休眠，应用唤醒锁仍持有 |
| 约 30 秒时开始第二次检查 | 请求等待 45 秒后触发 `ReadTimeout` |
| 本轮结束 | 总计 **75.07 秒**，只取得 1 次成功轮询，未完成 6 分钟目标 |
| 系统服务状态 | `ProxyService` 仍为 `isForeground=true` |
| 系统电源状态 | `PGProxy:LocalApi` 的 `PARTIAL_WAKE_LOCK` 显示 **`DISABLED`、`isFrozen=true`** |
| USB 对照 | 转发到手机同一 `8889` 端口后也出现读取超时 |

因此，前台服务与申请唤醒锁不足以保证这台手机在默认厂商策略下继续执行。系统明确报告应用被冻结，且 USB 与局域网访问同时超时，不能将这次失败仅归因于 Wi-Fi 链路；也没有证据把它当作 Google 上游故障。

随后通过应用“设置 → 后台耗电管理”进入系统页面，并依次进入“应用详情 → 电量 → 后台耗电管理”，将“智能控制后台耗电”改为“允许后台耗电”。返回应用后，电池优化状态同时显示“已忽略 Android 电池优化”，属于此次系统设置操作连带生效的条件。这里只记录该 vivo 设备实际显示的路径，其他厂商与系统版本可能不同。

```powershell

  --base-url http://手机局域网IP:8888 `
```

`--live` 会使用真实生成额度。复现时分别核对 LAN 关闭／开启两种行为，不能只验证 USB 转发。不要把端口、密钥、启停或锁屏操作与正在生成的请求交叉执行。
